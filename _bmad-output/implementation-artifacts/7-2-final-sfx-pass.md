## Story

As a player,
I want distinct, punchy sounds for every key event,
so that I can play partly by ear.

**Requirements:** FR63, FR28 (shift click feedback on the input frame), GFR32 (audible tells, from the readiness report), GFR64 (SFX Musts and per-boss glitch). Additional: AD-09 (AudioManager owns playback; requests via EventBus; Sample playback on web), D-049 (every `AttackDef.tell_sfx` points to a boss tell cue), project-context Platform & Build Rules (no live audio effects; pre-rendered assets only).

Depends on: 2.4 (shift click, `play_sfx`), 3.1 (`boss_tell_started`, `AttackDef.tell_sfx`), 3.2 (thud and chime placeholders, `hit_landed`, `patched_applied`), 3.6 and 3.8 (duck squeak, defeat squeak), 5.1 (Null Pointer hum), 7.1 (AudioManager music plumbing, which this story must not break). Window: Nov 26–29 (Epic 7).

## Acceptance Criteria

**Must sounds are final (FR63, GFR64)**

1. **Given** the SFX in `game/assets/audio/sfx/` generated by the committed script `game/tools/gen_sfx.py` (the replacement for `gen_shift_sfx.py`), **When** the corresponding events fire, **Then** every Must sound is final and plays: `shift_left.wav` and `shift_right.wav` (distinct, `<<` and `>>`), `hit.wav` (landed hit on the boss in the base state), `hit_resisted.wav` (the resisted thud, UNPATCHED), `patched_chime.wav` (Patched applied), `duck_squeak.wav` (duck line start and defeat squeak), the SIGSEGV alarm (the Segfault boss tell cue, see AC 3), one glyph-glitch sound per boss (`glitch_infinite_loop.wav`, `glitch_null_pointer.wav`, `glitch_segfault.wav`), the Null Pointer hum (code-generated, unchanged, see D-S72-9), `player_hit.wav`, `phase_roar.wav` and `defeat.wav`.
2. **And** the generator is deterministic: running `python3 game/tools/gen_sfx.py` twice gives byte-identical WAV files, and it needs only the Python standard library (no venv, no encoder). Output is 16-bit mono PCM at 22050 Hz, peak at or below 0.8 of full scale, no clipping, and every clip ends without a click (fade-out at the end).
3. **Given** the three bosses, **When** a boss attack's tell starts, **Then** `AudioManager` plays that boss's one tell cue (`tell_infinite_loop.wav`, `tell_null_pointer.wav`, `tell_segfault.wav`, the last one being the SIGSEGV alarm), and every `AttackDef.tell_sfx` of the three real bosses (11 attack resources) is one of these three ids. The test boss fixture keeps its own ids. `AttackDef.validate()` (or a data validation test) fails when a real-boss attack names an id outside the known cue set.
4. **And** the glyph-glitch sound of a boss plays on each `boss_phase_changed` of that boss with phase index 1 or 2 (the phase entries), and `phase_roar.wav` plays on `boss_roar_started`; `defeat.wav` plays on `boss_defeated` (the existing once-per-fight duck squeak stays unchanged).
5. **And** `hit_landed` on the boss plays `hit.wav` in the BASE state and `hit_resisted.wav` in the UNPATCHED state; the PATCHED state plays only the `patched_chime.wav` (via `patched_applied`), not a second hit sound. `player_damaged` plays `player_hit.wav`.
6. **Given** SFX play requests, **When** more than the pool size of one-shots overlap, **Then** playback goes through a pooled set of SFX players on the `SFX` bus (`SFX_POOL_SIZE`, see D-S72-4); the shift click keeps its own dedicated player (`ShiftSfx`, a new click cuts the previous one, as in 2.4) and is never stolen by another sound; the duck squeak keeps its `DuckSqueak` player (3.6). No request is dropped silently for a missing stream (a missing id logs a `Log.warn` once).
7. **And** nothing plays before the first input (the 1.4 unlock gate is unchanged), and no bus effects are added (the 1.4 bus test stays green).

**Shift click timing (FR28, the 2.4 check moved here)**

8. **Given** the input frame of a `<<` or `>>` shift, **When** `EventBus.register_shifted` is emitted, **Then** `AudioManager.play_sfx` is called in that same tick (no `call_deferred`, no timer), with the distinct stream for the direction. Verified by a GUT test on the juice director, and by the F9 overlay / `Log` debug line `shift` on the input frame in Chrome and Firefox (human, see the checklist).

**Automatable checks and data**

9. **And** a unit test loads all SFX ids the code references (every stream in the registry), checks each is 16-bit mono 22050 Hz, non-empty, and shorter than 1.0 s (the tells must be short: a tell is at least 20 frames, D-049), and checks the peak level from AC 2.
10. **And** the generator is covered by a test that re-runs it into a scratch directory and compares bytes with the committed files (or, if running Python from GUT is not practical, a CI-free check documented in the story notes). Choose the cheaper option and record it.
11. **And** `game/assets/audio/sfx/README.md` lists every file, its use, its source ("generated by `game/tools/gen_sfx.py`, CC0 by construction") and the placeholder/final status. The README replaces the placeholder note in `deferred-work.md` for SFX.

**Human checks (not automated, recorded in the checklist below; the story stays `review` until these are done)**

- H-S72-1 Chrome and Firefox: `<<` / `>>` click heard on the input frame (F9 overlay shows `shift` on the same frame), no audible delay on a second press within 6 frames.
- H-S72-2 Tiziano listens to the full set in the editor (or web build) and approves or asks for a regenerate with new parameters (the generator is the single source for changes).
- H-S72-3 Balance check on the web build: tells audible over the boss music, no clipping on the hit + chime + squeak overlap.

- **D-S72-1 [design call]** One stdlib-only generator `game/tools/gen_sfx.py` replaces `gen_shift_sfx.py`. No numpy, no venv (the scratchpad venv is not needed; WAV needs no encoder). Deterministic: fixed constants, no `random`, a fixed-seed LFSR for noise.
- **D-S72-2 [design call]** Final file list (16 one-shots + 1 code loop):
  `shift_left`, `shift_right`, `hit`, `hit_resisted`, `patched_chime`, `duck_squeak`, `tell_infinite_loop`, `tell_null_pointer`, `tell_segfault` (= SIGSEGV alarm), `glitch_infinite_loop`, `glitch_null_pointer`, `glitch_segfault`, `phase_roar`, `defeat`, `player_hit`. - **D-S72-4 [design call]** `SFX_POOL_SIZE = 8`; round-robin with steal of the oldest player when none is free. Shift click (`ShiftSfx`) and the squeak (`DuckSqueak`) stay on their own players and are never stolen.
- **D-S72-5 [design call]** Glitch sound on each phase entry of index 1 and 2 (the same moment the music glitches, D-S71-1). Phase roar on `boss_roar_started`. Defeat stinger on `boss_defeated` next to the existing squeak.
- **D-S72-6 [design call]** Target design: a BASE boss hit plays `hit` (new); the UNPATCHED thud is `hit_resisted`; a PATCHED hit has no extra sound because the chime is the Patched cue.
- **D-S72-7 [design call]** Sound lengths: shift clicks ≈ 40–60 ms (keep the snappy 2.4 feel), hits 60–120 ms, tells 200–300 ms (≥ 20 frames is 333 ms, so the cue is audible at tell start and does not outlast the tell), roar and defeat up to 0.8 s, glitch 150–250 ms.
- **D-S72-8 [design call]** Peak at or below 0.8 full scale in every file; no per-file loudness normalisation beyond that. Balance is H-S72-3.
- **D-S72-9 [design call]** Null Pointer hum: unchanged. It is a seamless code-built loop already tuned in 5.1 (D-S51-3); it counts as final. No file is committed for it.
- **D-S72-10 [design call]** Unknown tell id: no sound, one `Log.warn` (never a fallback blip, so a missing cue is visible in the log).
